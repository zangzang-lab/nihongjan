## Candidate pronunciation rule

For sentence-level learner-facing pronunciation, grammatical particles should use:

- は -> wa
- へ -> e
- を -> o

This must be token/POS-aware.

A character-level replacement is explicitly rejected because it can corrupt lexical strings such as おはよう, やはり, はず, and similar words.

The project already has an offline generator that uses Fugashi + Unidic + Pykakasi, but those Python dependencies are not installed in the current audit environment and outbound package installation is unavailable.

Therefore the existing 6,615 derived sentence records have not been bulk-regenerated by an unsafe heuristic.

## Safe deterministic presentation normalization

The current derived assets contain full-width question/exclamation marks in Romaji output:

- N5: 202 ? character occurrences, across 200 records
- N4: 2 occurrences, across 2 records
- N3: 2 occurrences, across 2 records

The intended derived/presentation normalization is:

- ？ -> ?
- ！ -> !
- full-width space -> ASCII space

This is safe because it changes presentation punctuation only and does not alter the Japanese source.

It has not been silently pushed into the production/Lovable repository.
